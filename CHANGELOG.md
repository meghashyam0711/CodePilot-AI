## [0.4.1] - 2026-10-23

### Fixed
- **Pre-Apply Snapshot Relative Path Preservation (Phase 14.1 / TASK-AUD-01):** Fixed `create_patch_backup()` in `src/codepilot/core/recovery.py` to mirror original relative directory paths under `.codepilot/backups/<patch_id>/` and added incremental collision counter, preventing backup overwrites when multi-file patches touch files with identical basenames across distinct subdirectories. Maintained full backward compatibility for `rollback_patch()`.
- **AI Test Failure Auto-Repair Patch Pipeline (Phase 14.2 / TASK-AUD-02):** Implemented target failure parsing, repair prompt construction, code extraction (`_integrate_repaired_code`), unified diff generation, and pending patch staging in `analyze_test_failure()` (`src/codepilot/core/test_analyzer.py`) for live model providers (`ollama`, `standalone`). Preserved explanation-only mode when `generate_patch=False` and enforced mandatory user approval gate.
- **Clarification Route Exception Handling in Patch Preview (Phase 14.3 / TASK-AUD-03):** Updated `generate_preview_patch()` in `src/codepilot/core/fixer.py` and CLI to recognize `TaskRoute.CLARIFICATION`, bypass code extraction, populate `clarification_question` in `PatchBundle`, display a dedicated Rich panel, and return cleanly without raising `FixError`.
- **Case-Insensitive & Whitespace-Tolerant # AI-DOCS Marker Detection (Phase 14.4 / TASK-AUD-04):** Added `instruction_type` on `FilePatch` and updated `apply_approved_patch()` in `src/codepilot/core/patcher.py` with case-insensitive, whitespace-tolerant regex matching (`#\s*ai-docs?\b`) to ensure all docstring marker variants strictly trigger AST structural invariance verification before writing to disk.
- **Windows Python Interpreter Quoting and Argument Token Normalization (Phase 14.5 / TASK-AUD-06):** Updated `detect_safe_test_command()` in `src/codepilot/core/tester.py` to quote `sys.executable` when spaces are present, expanded `validate_test_command()` to accept quoted executable paths while strictly blocking shell injection operators, and normalized split arguments in `run_project_tests()` to resolve Windows `CreateProcessW` execution cleanly.
- **Dynamic GGUF Context Window Allocation & Overflow Clamping (Phase 15 / TASK-AUD-05):** Updated `_get_or_load_model()` in `src/codepilot/core/models/standalone_client.py` to initialize `n_ctx` to `max_context_tokens` (default 2048 or user configured) rather than clamping to `2 * max_tokens`, tracked `_current_n_ctx`, and added context overflow detection with safe output token clamping in `generate()` to prevent llama.cpp native crashes on large prompts.
- **PlanTask Target Symbol Context Retention (Phase 15 / TASK-AUD-07):** Added `target_symbol` and `target_symbol_type` attributes to `PlanTask` in `src/codepilot/core/planner.py`, forwarded them from `InstructionComment` in `generate_plan()`, and provided backward-compatible dictionary deserialization, allowing downstream task execution to know the exact target symbol without falling back to line proximity.
- **Deeply Nested AST Symbol Extraction & Resolution (Phase 15 / TASK-AUD-08):** Implemented recursive hierarchical symbol matching in `_find_ast_symbol_span()` in `src/codepilot/core/context/engine.py` supporting arbitrarily nested classes and methods (e.g., `Outer.Inner.method`), and updated `SymbolResolver` in `src/codepilot/core/parser/symbol_resolver.py` to recursively resolve nested class methods into qualified names.
- **System Prompt and Context Wrapper Overhead Token Budgeting (Phase 15 / TASK-AUD-09):** Incorporated `DEFAULT_SYSTEM_OVERHEAD_TOKENS = 400` into `_estimate_tokens(..., include_overhead=True)` in `src/codepilot/core/context/engine.py` to reserve prompt capacity for system instructions and `<untrusted_repository_context>` wrapper delimiters, preventing prompt truncation near the context limit.

### Added
- **Engineering Remediation & Reliability Regression Test Suite:** Added 22 new deterministic regression tests (14 from Phase 14, 8 from Phase 15) across `tests/test_phase9_security_recovery.py`, `tests/test_fix.py`, `tests/test_test.py`, `tests/test_models.py`, `tests/test_plan.py`, and `tests/test_context_engine.py`, expanding the automated test suite to **391 passing tests across 25 modules** (100% pass rate).

## [0.4.0] - 2026-10-22

### Added
- **Standalone GGUF Backend Hardening & Caching:** Added thread-safe lazy model instance caching via `_get_or_load_model()` in `StandaloneGGUFClient` to avoid reloading weights across consecutive inference calls. Added configurable GPU layer offloading (`n_gpu_layers`) with conservative CPU-only default. Added comprehensive deterministic unit tests (12 tests) for standalone GGUF execution without requiring external dependencies, weights, or GPU.
- **Model Weight Protection:** Added `.gitignore` rules for `models/*.gguf`, `*.gguf`, and `models/` to prevent large binary weights from leaking into Git history.
- **Unified Diff Staging & Inspection:** Connected `fixer.py` to `ProjectContextEngine` and `BaseModelClient` to generate context-grounded code modifications staged non-destructively in `.codepilot/patches/pending_patch.json`. Added `codepilot diff` CLI command with Rich syntax highlighting.
- **Pre-Apply Snapshots & Safe Rollback:** Implemented `create_patch_backup()` taking full pre-modification snapshots in `.codepilot/backups/<patch_id>/` with cryptographic `manifest.json`. Added `codepilot rollback` CLI command (`--list`, `--patch-id`) to restore original files non-destructively without Git resets.
- **Sandboxed Test Runner & AI Error Correction:** Implemented safe test discovery (`pytest`), preview mode (`codepilot test --preview`), exclusive PID file locking (`.codepilot/test.lock`), 64 KB stream bounds, and single-turn error correction (`codepilot test --approved --fix`).
- **Standalone Local GGUF Runtime:** Implemented `StandaloneGGUFClient` using optional `llama-cpp-python` with cryptographic SHA256 weight verification, fully decoupled from Ollama.
- **Centralized File Ownership & Boundary Policies:** Implemented `resolve_project_root()`, `classify_file_ownership()` (5 ownership tiers), and `check_file_permission()` (6 granular operations).
- **Phase 11 GGUF Patch Generation Integration:** Added `unwrap_nested_function_body()` and `find_enclosing_function()` in `src/codepilot/core/fixer.py` to safely unwrap redundant function signatures without weakening syntax validation or security checks. Added Rule 7 (`REPLACEMENT SCOPE`) to `SYSTEM_INSTRUCTION` in `src/codepilot/core/context/prompt.py`. Added comprehensive test suite `tests/test_phase11_gguf_integration.py`.
- **Model Output Extraction & Quality Optimization (Phase 12):** Improved `extract_code_from_completion()` in `src/codepilot/core/evaluation/metrics.py` to support closed and unclosed markdown fences (supporting both Unix `\n` and Windows `\r\n`) and added `_is_probable_code()` to prevent conversational preambles from leaking into generated source files. Updated `src/codepilot/core/context/prompt.py` with code-first output formatting for compact coding LLMs. Added 16 deterministic evaluation tests in `tests/test_evaluation.py` covering all 8 benchmark categories.
- **Standalone Model Factory Override Forwarding (Phase 13B.2):** Fixed `create_model_client()` to forward explicit `override_model` parameters to `StandaloneGGUFClient` as `model_path` (handling relative paths anchored to `project_root`). Added 5 focused unit tests in `tests/test_models.py`.
- **Evaluation Runner Context Encapsulation (Phase 13B.3 / Phase A):** Fixed `EvaluationRunner.evaluate_cases()` to provide `case.source_code` inside `<untrusted_repository_context>`, clearly separating task instructions from repository code without altering production `fix` flows.
- **Validation Test Denominator Correction (Phase 13B.3 / Phase A):** Corrected validation test counting to include cases with empty extractions as test failures (`False`) rather than skipping them, preserving truthful pass-rate denominators.
- **Diff Hygiene Metric Audit & Coverage (Phase B):** Audited `calculate_diff_hygiene()` against comments, docstrings, defensive checks, signature changes, and excessive bloat; added 6 focused tests in `tests/test_evaluation.py`.
- **Prompt Guidelines for Minimal Diffs & Clarification (Phase D & E):** Updated `SYSTEM_INSTRUCTION` in `src/codepilot/core/context/prompt.py` to strictly preserve function signatures, avoid extraneous comments/checks, and balance clarification requests on ambiguous tasks vs direct progress on clear instructions. Added deterministic tests in `tests/test_evaluation.py`.
- **Prompt Boundary & Context Delimiter Echo Hardening (Stage I):** Updated `SYSTEM_INSTRUCTION` Rule 6 & 7 explicitly stating that `<untrusted_repository_context>` is a prompt-only delimiter that must never appear in generated source code or code fences. Added `_strip_context_delimiter_lines()` in `src/codepilot/core/evaluation/metrics.py` to narrowly filter standalone echoed context tags while preserving valid code, indentation, and strings/comments containing angle brackets. Added 11 focused regression tests in `tests/test_evaluation.py`.
- **Real-Model Evaluation v3 Benchmark Execution (Stage J):** Executed single canonical 8-category benchmark run on CPU using local `Qwen2.5-Coder-1.5B-Instruct` GGUF. Verified Stage I prompt boundary and code-extraction hardening: syntax validity restored from 37.5% to 100.0% (PASS, +62.5 pp), validation test pass rate increased to 85.7% (PASS, +71.4 pp vs v2), instruction following maintained at 87.5% (PASS), clarification accuracy maintained at 87.5% (PASS), and diff hygiene improved to 60.7% (+28.8 pp vs baseline, +4.7 pp vs v2). Generated and verified immutable reports `reports/evaluation_qwen_1.5b_cpu_v3.md` and `reports/evaluation_qwen_1.5b_cpu_v3.json`.
- **Release Readiness Audit (Stage K):** Completed comprehensive, evidence-based audit of CodePilot AI v0.4.0 verifying artifact immutability, benchmark metric recovery, diff hygiene characteristics, security boundary mechanisms, and test stability (303/303 passing tests). Published `reports/release_readiness_audit_v0.4.0.md` with final verdict **READY WITH LIMITATIONS**.
- **Diff Hygiene, Filename Sanitization, and Clarification Hardening (Stage L):** De-conflicted `SYSTEM_INSTRUCTION` in `src/codepilot/core/context/prompt.py` (Rule 1 & Rule 2) to instruct compact, minimal diffs and explicitly forbid unprompted defensive validation, `isinstance` checks, unrequested argument assertions, extraneous comments, and unnecessary control flow restructuring. Implemented in-memory string-level `sanitize_filename()` in `src/codepilot/core/security.py` (and re-exported in `src/codepilot/core/__init__.py`) using safe basename extraction and iterative traversal sequence (`..`) stripping, while keeping filesystem boundary enforcement (`validate_target_path()`) distinct and intact. Updated Rule 6 to guide models to isolate basenames before stripping traversal tokens. De-conflicted clarification handling (Rule 4 & Rule 7) to require models to emit only a single concise question starting with "Please clarify..." without code fences or speculative code when essential requirements are missing. Added 12 deterministic unit tests across `tests/test_phase9_security_recovery.py`, `tests/test_context_engine.py`, and `tests/test_evaluation.py`. - **Real-Model Evaluation v4 (Stage M):** Conducted authorized single CPU evaluation of `Qwen2.5-Coder-1.5B-Instruct` GGUF. - **Task Router and Clarification Prompt Separation (Stage N):** Addressed the Stage M v4 prompt mode-collapse regression by isolating clarification instructions from code-generation instructions. Restored `SYSTEM_INSTRUCTION` in `src/codepilot/core/context/prompt.py` to a pure, code-first generation prompt completely devoid of universal clarification triggers (such as verbatim "Please clarify..."). Added 28 new deterministic unit tests in `tests/test_task_router.py`. Published completion report `reports/stage_n_task_router_completion.md`. Real-model inference was not run.

### Changed
- **Fixed Model Client Interfaces:** Corrected `ModelResponse` argument from `completion` to `content` in `StandaloneGGUFClient.generate()`. Removed unsupported `modified_at` field from `ModelInfo` creation in `list_available_models()`.
- **Dynamic AI Status Inspection:** Updated `get_status()` in `src/codepilot/core/app.py` to evaluate model provider connectivity dynamically via `client.is_available()`.
- **Integrated File Permission Gate:** Wired `check_file_permission()` directly inside `apply_approved_patch` in `src/codepilot/core/patcher.py`.
- **Modernized Diagnostics & CLI Presentation:** Replaced static foundation placeholders in `codepilot status` and `codepilot doctor` with live diagnostic results.
- **Automated Test Suite Expansion:** Expanded test suite to **369 passing tests across 25 modules** with 100% pass rate.

### Security
- **Canonical Path Traversal Guards:** Implemented `validate_target_path()` using `pathlib.Path.resolve()`, strictly blocking `../../` directory traversal and symlink escapes outside the project root.
- **Protected File Enclaves:** Refuses access or modification to `.env`, credentials, private keys, `pyproject.toml`, and `.git/`.
- **Binary File Guard:** Detects null bytes in the initial 8 KB of files to prevent binary corruption.
- **Secret Sanitization:** Automated regex scrubbing of API tokens, Bearer headers, passwords, and private key blocks in logs and console outputs.
- **In-Memory Validation Test Restrictions:** Restricted builtins in `run_validation_test_safely()` by disallowing `open`, `breakpoint`, `input`, `__import__`, `eval`, `exec`, `quit`, and `exit`. Documented that in-memory namespace restrictions provide defense-in-depth and do not constitute an OS-level sandbox.
